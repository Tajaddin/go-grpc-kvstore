method:    7 rounds; each round started a fresh server of the previous code
           (be98aa1) and ran the load once, then did the same for the

NOT an idle-machine measurement. Other jobs kept total CPU at roughly
45-100% (sampled before and after the runs), and throughput moved nearly
7x between runs of the same binary, so these numbers measure contention,
not the service. The spread swamps any difference between the two
versions, and they are not comparable with the May 2026 baseline below.
A second attempt that only started a run once background CPU averaged
under 30% for 3 s found no such window in 5 minutes.
